AUTOMATISATION DES INSCRIPTIONS TFT
==================================

FONCTIONNEMENT
--------------
Une nouvelle réponse au Google Form déclenche GitHub Actions. Le workflow lit le
Google Sheets et les photos Drive, valide les inscriptions et les autorisations,
génère le JSON public et les photos consenties, puis publie seulement ces fichiers
sur la branche main. Un contrôle quotidien repère aussi les modifications ou
suppression faites directement dans le classeur.

Aucune page admin locale ni aucun token ne sont nécessaires à chaque inscription.
Le journal de synchronisation et le manifeste de traçabilité restent dans un
Google Sheets privé. Le workflow n’affiche que des nombres et des statuts, jamais
les noms ou les liens de photo.

AVANT DE CONFIGURER
-------------------
Le formulaire ne doit pas être modifié. Selon la règle confirmée par
l’organisateur, le parcours de paiement recueille déjà le consentement et le
formulaire indique que la photo facultative peut être partagée sur le site
public. L’automatisation traite donc l’envoi d’une photo comme le signal
d’autorisation. Aucune colonne de consentement supplémentaire n’est requise.

Une photo est facultative. Si une photo est fournie mais que son lien Drive est
absent, invalide, inaccessible ou associé à plusieurs inscriptions, la
synchronisation s’arrête sans publier de changement.

1. Dans le Google Sheets des réponses, créer un onglet `SyncConfig` :

   A1 : BRACKETS_LOCKED
   B1 : FALSE

   Tant que les tableaux ne sont pas définitifs, laisser FALSE. Quand ils sont
   verrouillés pour la compétition, passer B1 à TRUE. Toute inscription qui
   ajouterait, retirerait ou déplacerait un participant après verrouillage bloque
   la publication au lieu de refaire un tirage déjà publié.

3. Créer un Google Sheets privé pour les rapports. Ajouter deux onglets nommés
   exactement `PhotoManifest` et `SyncStatus`, puis laisser leurs cellules vides.
   Ne pas partager ce classeur publiquement.

GOOGLE CLOUD
------------
1. Dans le projet Google Cloud, activer Google Drive API.
2. Activer aussi Google Sheets API.
3. Le compte de service `tft-public-sync` n’a besoin d’aucun rôle IAM au niveau
   du projet. Partager le Google Sheets de réponses en lecture avec son adresse
   e-mail.
4. Partager en lecture avec ce compte le dossier Drive où les photos envoyées par
   le formulaire sont enregistrées.
5. Partager le Google Sheets privé de rapports en modification avec ce compte.

Ne crée pas de clé JSON. Si la politique Google Cloud bloque les clés, utiliser
Workload Identity Federation pour que GitHub Actions reçoive des identifiants
temporaires. Dans Google Cloud Shell, exécuter les commandes suivantes. Elles
créent un fournisseur limité au dépôt, à la branche `main` et à ce workflow
précis. Remplacer les deux valeurs demandées par l’identifiant du projet et
l’adresse e-mail complète du compte de service :

    read -r -p "Google Cloud project ID: " PROJECT_ID
    read -r -p "Service account email: " SERVICE_ACCOUNT
    PROJECT_NUMBER="$(gcloud projects describe "$PROJECT_ID" --format='value(projectNumber)')"
    POOL_ID="github-actions"
    PROVIDER_ID="tft-public-sync"

    gcloud services enable iamcredentials.googleapis.com --project="$PROJECT_ID"

    gcloud iam workload-identity-pools create "$POOL_ID" \
      --project="$PROJECT_ID" \
      --location="global" \
      --display-name="GitHub Actions"

    gcloud iam workload-identity-pools providers create-oidc "$PROVIDER_ID" \
      --project="$PROJECT_ID" \
      --location="global" \
      --workload-identity-pool="$POOL_ID" \
      --display-name="TFT public sync" \
      --issuer-uri="https://token.actions.githubusercontent.com" \
      --attribute-mapping="google.subject=assertion.sub,attribute.repository=assertion.repository" \
      --attribute-condition="assertion.repository == 'Therrayyyy/TFT_Series_NOGI' && assertion.ref == 'refs/heads/main' && assertion.workflow_ref == 'Therrayyyy/TFT_Series_NOGI/.github/workflows/public-tournament-sync.yml@refs/heads/main'"

    gcloud iam service-accounts add-iam-policy-binding "$SERVICE_ACCOUNT" \
      --project="$PROJECT_ID" \
      --role="roles/iam.workloadIdentityUser" \
      --member="principalSet://iam.googleapis.com/projects/${PROJECT_NUMBER}/locations/global/workloadIdentityPools/${POOL_ID}/attribute.repository/Therrayyyy/TFT_Series_NOGI"

    echo "projects/${PROJECT_NUMBER}/locations/global/workloadIdentityPools/${POOL_ID}/providers/${PROVIDER_ID}"

Garder la dernière valeur affichée : c’est l’identifiant du fournisseur à saisir
dans GitHub. Ces commandes ne créent aucune clé et n’accordent pas de rôle au
compte de service sur tout le projet. Si la création du pool ou du fournisseur
est refusée, arrêter et demander à l’administrateur Cloud de vérifier la
permission de gérer Workload Identity Federation ; ne pas relâcher la politique
qui interdit les clés.

GITHUB
------
Dans les paramètres du dépôt TFT_Series_NOGI :

1. Dans Actions > General, autoriser les workflows à lire et écrire le contenu du
   dépôt.
2. Dans Secrets and variables > Actions > Variables, créer :
   - `GCP_WORKLOAD_IDENTITY_PROVIDER` : ressource complète affichée par la
     dernière commande Cloud Shell (`projects/.../providers/tft-public-sync`).
   - `GCP_SERVICE_ACCOUNT` : adresse e-mail du compte `tft-public-sync`.
   - `SPREADSHEET_ID` : identifiant du Google Sheets de réponses.
   - Variable `SYNC_MANIFEST_SPREADSHEET_ID` : identifiant du Google Sheets privé
     de rapports.
3. Aucune clé Google n’est nécessaire. Ne jamais ajouter une clé, un token ou un
   classeur au dépôt Git.

GOOGLE APPS SCRIPT
------------------
1. Ouvrir le Google Sheets des réponses, puis Extensions > Apps Script.
2. Copier le contenu de `automation/apps_script/on_form_submit.gs` dans l’éditeur.
3. Créer un fine-grained personal access token GitHub limité au seul dépôt
   TFT_Series_NOGI avec la permission Actions: read and write. Ne pas utiliser un
   token déjà envoyé dans un chat ; le révoquer d’abord.
4. Dans Apps Script > Paramètres du projet > Propriétés du script, ajouter la
   propriété `GITHUB_DISPATCH_TOKEN` et coller le nouveau token dans sa valeur.
   Le token n’est jamais écrit dans le code.
5. Dans l’éditeur Apps Script, sélectionner `installRegistrationTrigger`, cliquer
   Exécuter et accepter les autorisations. Le déclencheur s’exécute sous le compte
   Google du propriétaire du classeur.

Le déclencheur envoie un événement à GitHub. GitHub Actions utilise ensuite son
propre jeton temporaire `GITHUB_TOKEN` pour publier ; le token Apps Script ne peut
pas modifier le contenu du dépôt.

VÉRIFICATION
------------
1. Lancer manuellement `Sync public tournament` dans l’onglet Actions pour le
   premier test.
2. Vérifier le résultat dans GitHub > Actions. Les erreurs ne publient aucun
   fichier public. Les rapports privés sont enregistrés dans le Google Sheets
   configuré.
3. Après un test réussi, soumettre une inscription de test et confirmer qu’un
   workflow est déclenché. Supprimer ensuite la réponse de test et vérifier la
   réconciliation quotidienne.

Le workflow conserve les tableaux existants lorsque la liste de la catégorie
reste identique. Avant verrouillage, une catégorie dont la liste change reçoit un
nouveau tirage. Après verrouillage, tout changement de liste bloque la
publication. L’outil ne fait jamais de force-push.
