TFT SERIE NO-GI #1 - APPLICATION PUBLIQUE
=========================================

ROLE DE CE DEPOT
----------------
Ce depot contient uniquement l'application publique de consultation. Les visiteurs
peuvent lire les tableaux publies, telecharger les PDF et imprimer la page.
L'application ne permet pas d'importer un fichier d'inscriptions, de generer ou
de modifier un tirage.

Le code de ce depot est public et peut etre consulte ou copie. La version publique
ne contient pas les fonctions d'administration. Il n'y a pas de commande ou de
mot de passe admin a utiliser dans ce depot.

ADMINISTRATION ET DONNEES PRIVEES
---------------------------------
L'administration est prevue pour fonctionner automatiquement : apres une
configuration unique, une nouvelle reponse Google Form declenche GitHub Actions,
qui synchronise les inscriptions et publie le JSON et les photos autorisees sur
la branche main. Le guide de configuration est
automation/SETUP.txt. Tant que les secrets/variables GitHub et le declencheur
Apps Script ne sont pas configures, aucune synchronisation automatique n'est
active.

Seul le compte GitHub de l'organisateur doit avoir les droits d'ecriture sur le
depot. Les visiteurs peuvent voir ou copier le code, mais ne peuvent pas modifier
le site sans acces d'ecriture au depot.

Les inscriptions, les classeurs Excel, les manifestes de tracabilite, les cles
Google et les tokens ne doivent jamais etre commites ici. Le fichier
tournament_public.json et les photos de fighter_photos sont visibles
publiquement. Ne publier que les informations et images que l'organisateur est
autorise a rendre publiques, en particulier pour les mineurs.

MISE A JOUR ET SUIVI
--------------------
Apres configuration, chaque nouvelle reponse au formulaire declenche le
workflow `Sync public tournament`. Un controle quotidien sert aussi a reperer
les changements directs apportes au classeur. Les exécutions, leur date, les
erreurs et un resume des donnees publiees sont consultables dans GitHub > Actions.
Le statut detaille et la tracabilite des photos sont conserves dans le Google
Sheets prive configure, pas dans ce depot.

Le workflow preserve les tableaux lorsque la liste de la categorie n'a pas
change. La feuille SyncConfig!B1 permet de verrouiller les tableaux : lorsque la
valeur est TRUE, un changement de roster bloque la publication. Le workflow ne
fait jamais de force-push et ne pousse que tournament_public.json et
fighter_photos.

DEPLOIEMENT STREAMLIT
---------------------
L'application est lancee depuis app.py, avec requirements.txt. Elle est en mode
consultation uniquement; ne pas ajouter de variable d'environnement ou de
fonctionnalite admin a l'application publique.

En local, installer les dependances puis lancer la vue publique:

    py -m pip install -r requirements.txt
    py -m streamlit run app.py

Cette commande ne donne aucun acces d'administration.

REGLES DE COMPETITION
---------------------
- 1 combattant : affiche le seul inscrit, sans faux tableau.
- 2 combattants : finale directe.
- 3 combattants : poule Round Robin, chacun rencontre les deux autres une fois.
  Le classement et les statistiques sont a completer manuellement; aucun rang
  n'est pre-rempli dans la page ou le PDF.
- 4 combattants ou plus : arbre a elimination directe, avec qualifications
  d'office si necessaire et petite finale pour le bronze.
- Les combats et leurs liaisons sont consultables dans la page et dans les PDF.
- Les photos de profil publiees apparaissent dans les tableaux et les PDF.

CONFIDENTIALITE
---------------
Une application Streamlit publique rend son contenu visible a tous les visiteurs.
Le depot public rend egalement le code et l'historique Git consultables. Avant
chaque publication, verifier tournament_public.json et les photos de
fighter_photos ; ne publier que les informations et images autorisees, en
particulier pour les mineurs. Remplacer ou effacer un fichier dans la version
actuelle ne le retire pas automatiquement des anciens commits Git.
